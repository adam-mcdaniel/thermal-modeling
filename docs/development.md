# Developing on Frontier

**Purpose:** everything needed to move this project to Frontier, rebuild it, reproduce the results, and pick up where it left off.

## Moving the project

* **`cabinet_power_recon_gpu_energy_1ms.csv` (287 MB) isn't in git:** it's over GitHub's 100 MB limit. Copy it into the repository's root separately, for example `scp cabinet_power_recon_gpu_energy_1ms.csv <you>@dtn.ccs.ornl.gov:<repo path>/`. Only these read it:
  * `gpu/fit_water.py`;
  * step 5 of `gpu/gpu_validation.ipynb`;
  * step 6 of `gpu/gpu_model.ipynb`;
  * the long-run test in `gpu/gpu_control.ipynb`.

  Everything else works without it.
* **`data/rochpl-frontier/` holds symlinks to a Mac path** (`~/Documents/ampere/examples/hpl-trace`), so they'll arrive broken. On Frontier, point them, or `AMPERE_EXAMPLES`, at the traces' real location (see [data](background/data.md)).
* **The samples files in `gpu/samples/` (25 MB) are enough** to refit and rerun the model without the raw traces.
* **`.gitignore` excludes build outputs** (binaries, `target/`, `__pycache__`).

## Building

| What | Command | Needs |
|---|---|---|
| Model tools (`fit_gpu`, `predict_gpu`, `replay_gpu`) | `cd gpu && ./reproduce.sh` | a C compiler, plus Python with Ampere for `make_samples.py` |
| Runtime governor, stress workload, simulated test | `cd gpu/runtime && module load rocm && ./build.sh` | ROCm, Rust (`cargo`), network access to fetch tapir from GitHub |
| Just the simulated governor test | `cd gpu/runtime && python test_governor.py` | a C compiler, Python with numpy, pandas, matplotlib |

`reproduce.sh` uses `PYTHON` (default `~/miniconda3/envs/ampere_dev/bin/python`): set it to Frontier's Python environment. The notebooks are generated by `make_*.py`, then run with `jupyter nbconvert --execute`.

`tapir-thermal/.cargo/config.toml` uses `gcc` as the linker, as tapir does, because `rust-lld` can't find the system libc on Frontier login nodes.

## First runs on hardware, in order

Each step checks something the previous ones rely on:

1. **Build:** `./build.sh`. Watch for `tapir-thermal: no ROCm headers ... using the stub header`, which means `ROCM_PATH` isn't set.
2. **Telemetry works:** `./thermal_stress square --period 2 --seconds 20 --samples t.txt`. Check that `t.txt` shows power rising to ~500 W and the junction climbing when on.
3. **Calibrate:** `./thermal_stress recipe --samples gpu0.txt && ../fit_gpu gpu_fit.h gpu0.txt`. Check the held-back error is under ~1 °C and there are no warnings.
4. **The governor loads, and decides without acting:** `TAPIR_PROFILERS="thermal(fit=gpu_fit.h,log=dry.csv,dry_run=1)" LD_PRELOAD=$PWD/libtapir_thermal.so ./thermal_stress random --work`. Check the start-up line `thermal: governing GPU ...` and that `dry.csv` has a model junction close to the measured one.
5. **A/B on fixed work:** run `random --work` without and with the governor, and compare runtime and junction swings.
6. **Real application:** the same on rocHPL.

## Things to measure that decide the design

| Question | Why it matters | How |
|---|---|---|
| How does runtime scale with a power cap? | A cap could be far cheaper than gaps (see [sleeps and caps](control/sleeps-and-caps.md)) | Run a fixed job at 2–3 power caps |
| What does the GPU draw during a 1–5 ms gap? | The governor assumes it drops to idle | `thermal_stress square --period 0.004 --samples gap.txt` |
| How long does a rocm_smi read take? | The 1 ms telemetry loop assumes it's fast | Time `tl_read` in a loop |
| How much does draining the stream for a gap cost? | Gaps discard launch-ahead | Compare `--work` runtimes with `max_gap=0` and with the default |
