# The model

Predict a GPU's junction temperature from its power, after calibrating once from power and the junction sensor. Everything lives in `gpu/`.

| Page | Answers |
|---|---|
| [Thermal model](thermal-model.md) | What the model is, and how to call it |
| [Calibration](calibration.md) | How its numbers are found, and what run to calibrate on |
| [Validation](validation.md) | How well it predicts data it never saw, across 20 GPUs |
| [Coolant](coolant.md) | How the water moves when a whole cooling group is busy |
| [Forecast](forecast.md) | The worst the junction could get, a few seconds ahead |

**Summary of results (real Frontier data):**

| Test | Junction error |
|---|---|
| Unseen last 40% of each run, against raw 1 °C sensor readings (20 GPUs) | 0.82 °C |
| Same, against half-second averages, which removes the sensor's flicker | 0.36 °C (worst GPU 0.75 °C) |
| Calibrated on rocHPL, predicting a different job on a different GPU in the same slot | 0.95 °C (0.44–1.58 °C) |
| Worst-case forecast, 1–10 s ahead | Held 97–100% of the time, largest miss 0.7 °C |

The notebooks:
* `gpu/gpu_validation.ipynb`: how good the model is.
* `gpu/gpu_model.ipynb`: how the model works.
* `gpu/gpu_control.ipynb`: the [control study](../control/README.md).

Each is generated by its `make_*.py`.
